# ===========================================================================
# HireSnap backend - runtime dependencies
# ===========================================================================
#
# WHAT IS IN HERE: the exact third-party import closure of the server entry
# point, backend/service/main.py (which uvicorn-loads service.api.app), plus
# pytest for the test suite. Nothing else. Every line is pinned.
#
# WHAT IS NOT IN HERE: the inference stack. Embedding, transcription and the
# Cosmos tokenizer live in the ml sidecar (ml/); the backend reaches them over
# HTTP through service/infrastructure/ml_sidecar.py and imports no ML library at all.
# torch, torchvision, torchaudio, transformers, sentence-transformers, moviepy,
# librosa, torchmetrics, torcheval, faiss-cpu, spacy, textattack, nltk, webrtcvad,
# twisted, aiobotocore, opencv-python, notebook, munch, protobuf, matplotlib and
# seaborn were removed with it - none of them was reachable from service.main.
#
# numpy, pandas and scikit-learn stay: candidate/vacancy matching (cosine
# distances, MinMaxScaler) is business logic that runs in the API process.
#
# WHY THE VERSIONS ARE PINNED: an unpinned install makes two builds a month apart
# produce two different images from the same commit (docs/KNOWN_GAPS.md 4). The
# previous file pinned only its first block and left the whole ML tail floating.
#
# PYTHON 3.9 IS THE TARGET: every pin below publishes a cp39 wheel, so the image
# builds without a compiler. Keep that property when you bump one - the base
# image has no build-essential any more.
#
# TWO SIBLING FILES, DELIBERATELY SEPARATE:
#   requirements-platform.txt  celery, redis, boto3 - only for the worker and S3
#                              images, imported lazily by service/infrastructure/
#   docker/requirements.lock.txt  this file, verbatim: the reproducible build
#
# THERE IS NO GPU SIBLING ANY MORE. requirements_external.txt (torch+cu116,
# tensorflow) is deleted: a file whose purpose is to install the inference stack
# into THIS interpreter is how the boundary erodes. The sidecar's image installs
# its own torch from ml/.
#
# HOW THIS LIST WAS COMPUTED: an AST walk from service/main.py over the local
# import graph, collecting the top-level third-party names. The walk crosses the
# whole of service/ (api, configuration, domain, repositories, services, shared,
# infrastructure), which is why the count grew when the package was flattened out
# of the old src/pipeline, src/services and src/utils split. Re-run it after
# adding an import to a module the entry point reaches - backend/tests/
# test_backend_structure.py enforces the shape, not this list.
# ===========================================================================

# --- auth -----------------------------------------------------------------
PyJWT==2.8.0
# cryptography is NOT optional here, even though PyJWT marks it as one.
# JWT_ALGORITHM defaults to RS256 (service/models/auth_models.py:95), and PyJWT
# only registers RSA backends when cryptography is importable. Without it
# jwt.encode() raises
#   NotImplementedError: Algorithm 'RS256' could not be found.
#   Do you have cryptography installed?
# so /signin and /signup answer 500 and the API cannot mint a single token.
# This pin was dropped during the vertical-slice refactor along with the ML tail
# that used to pull cryptography in transitively (twisted, textattack,
# aiobotocore, and an explicit 'cryptography' line in the original file); the
# AST walk that produced the trimmed list cannot see a dynamic import inside
# PyJWT, so the loss only shows up at request time. Keep it pinned directly:
# a dependency the only code path needs must not be inherited from a package
# that is one 'why is this here?' cleanup away from being removed.
cryptography==42.0.8
bcrypt==4.1.3
